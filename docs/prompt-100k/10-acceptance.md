### 10.2 视觉测试用例

每条用例包含"操作—预期—失败表现"三段。

**V01 银河俯视**

- 操作：启动，或按 `1`。
- 预期：中央有一条沿 25° 方向的中等长度亮棒，四条旋臂从棒端甩出，其中两条明显更亮。核球在最中心，比棒短而厚。
- 失败表现：旋臂从原点而非棒端出发；四条臂亮度完全一致；看不到棒；核球比盘还大。

**V02 银河侧视**

- 操作：按 `2`。
- 预期：画面中部有一条横贯的细亮带，中心位置明显鼓起并偏黄，两端渐细变暗。带内可见暗色缝隙。
- 失败表现：看到一个大圆盘（说明没有真正侧视）；光带厚度均匀（说明没有核球）；光带是一根硬边直线（说明没有厚盘与星晕）。

**V03 内部光带**

- 操作：按 `3`。
- 预期：相机位于盘内，视野中一条银河带横贯天空，中央亮、两侧暗，带中有一条明显的暗尘裂缝。背景星稀疏。
- 失败表现：画面过曝成白色；看不到裂缝；背景星比银河还亮。

**V04 本星系群**

- 操作：从银河层持续向外拉远，或点"本星系群"。
- 预期：银河系缩小成画面中的一个小旋涡，M31 在另一侧，明显更大。LMC/SMC 紧邻银河系。每个有名字的星系有标签。
- 失败表现：银河系消失；M31 与银河系大小相同；大小麦哲伦云跑到星系群边缘。

**V05 太阳系**

- 操作：点击太阳标记。
- 预期：太阳在中心发光，八大行星沿轨道分布，外侧行星间距明显更大（非线性映射）。
- 失败表现：内行星重叠；太阳比木星还小；看不到轨道。

**V06 地月系**

- 操作：在太阳系聚焦地球后继续放大。
- 预期：地球与月球同时可见，地球直径约为月球的 3.7 倍，两者之间有明显空隙。月球被照亮的一侧朝向太阳。
- 失败表现：月球紧贴地球；地球与月球大小接近；月球始终全亮或全暗。

**V07 月相变化**

- 操作：在地月系中推进时间。
- 预期：月球亮面形状从新月、上弦、满月、下弦连续变化，约 29.5 秒一个周期（1 秒 = 1 天）。
- 失败表现：月球亮度整体变化而不是形状变化；月相与公转位置不对应。

**V08 恒星系统**

- 操作：在银河层点击南门二。
- 预期：三颗恒星，A/B 较近，C（比邻星）在远处的小红点。比邻星旁有行星轨道。
- 失败表现：三颗星等距排列；比邻星与 A/B 一样大一样亮。

### 10.3 交互测试用例

**I01 旋转自由度**

- 操作：左键水平拖、垂直拖、斜向拖。
- 预期：三种方向都改变视角，垂直拖动改变俯仰角。
- 失败：只有水平拖动有效。

**I02 平移**

- 操作：右键拖动。
- 预期：画面内容沿拖动方向移动，注视点改变，旋转中心随之改变。
- 失败：右键无反应；或整块画面跳变。

**I03 点击与拖动分离**

- 操作：按住左键拖动 200px 后松开。
- 预期：不打开任何面板。
- 失败：拖动结束弹出面板。

**I04 未对准不下钻**

- 操作：把视角对准一处无标记的空白盘面，滚轮放大到最小。
- 预期：停在最小半径，显示"点击太阳或其他恒星以进入"。
- 失败：直接进入太阳系。

**I05 对准下钻**

- 操作：把太阳标记移到屏幕中心，滚轮放大。
- 预期：进入太阳系。
- 失败：无反应或进入错误场景。

**I06 返回**

- 操作：进入太阳系后按 `Esc`。
- 预期：回到银河层，相机角度与半径与进入前接近。
- 失败：回到默认视角（丢失上下文）；或无法返回。

**I07 拾取准确度**

- 操作：依次点击太阳、行星、其他恒星。
- 预期：每次都打开正确对象的资料。
- 失败：点太阳打开行星面板；点空白打开最近对象。

**I08 深链接**

- 操作：地址栏依次输入 `#localgroup`、`#galaxy/edge`、`#galaxy/inside`、`#star/sirius`、`#solar`、`#earthmoon`。
- 预期：每个都进入对应状态，刷新后保持。
- 失败：白屏；或进入默认视角。

**I09 演示模式**

- 操作：按 `D`。
- 预期：UI 隐藏，相机自动运动；任意鼠标移动立即退出。
- 失败：退出后层级错乱；或 UI 无法恢复。

**I10 键盘完整可操作**

- 操作：仅用键盘完成 进入太阳系 → 选地球 → 进入地月系 → 返回。
- 预期：Tab/Enter/Esc 可完成全部流程。
- 失败：某一步必须用鼠标。

### 10.5 无头验证脚本

验证脚本放在 `tools/` 目录，但**不进入发布版本**（或发布但不在 README 宣传）。脚本使用 Chrome DevTools Protocol 或 Playwright，核心是注入探针。

关键设计：无头环境中 `requestAnimationFrame` 会被节流，因此不能依赖"等 5 秒再截图"。必须暴露 `window.__galaxy` 并手动驱动：

```js
// 在页面中注入
await page.evaluate(() => {
  window.__galaxy = {
    setLayer: (l) => transitionTo(l, { instant: true }),
    setCam: (theta, phi, radius) => { cam.tTheta = theta; cam.tPhi = phi; cam.tRadius = radius; },
    step: (n) => { for (let i = 0; i < n; i++) frame(performance.now() + i * 16); },
    layers: () => ({ layer, phase, focusId, radius: cam.radius })
  };
});

// 强制推进若干帧后再截图
await page.evaluate(() => window.__galaxy.step(30));
await page.screenshot({ path: 'shot-galaxy.png' });
```

测试脚本的检查项：

1. 页面加载后 `gl` 不为 null，控制台无错误。
2. `step(30)` 后画布非全黑（采样中心区域像素，亮度总和 > 阈值）。
3. 对每个深度链接：设置哈希 → `step(30)` → 读取 `layers()` 校验层级与半径。
4. 对每个层级截图，供人工比对视检。
5. 粒子数在预期范围：`gl` 层暴露 `passes` 数组，合计在 40 万–60 万之间（high）。

截图命令参考（Windows）：

```
chrome --headless=new --disable-gpu --enable-unsafe-swiftshader ^
  --window-size=1600,900 --virtual-time-budget=12000 ^
  --screenshot=out.jpg "file:///D:/.../index.html?quality=high"
```

注意事项：

- 注入 `* { transition: none !important; animation: none !important; }` 后再截图，否则 CSS 过渡会让 UI 停在半透明状态。
- 不要用无头 FPS 判断性能，SwiftShader 是软件渲染。
- 每次截图前用固定种子 `?seed=20261108`。
- 图片体积控制在 300KB 以内，避免仓库膨胀。

### 10.6 开源发布流程

仓库：`https://github.com/bietou123/galaxy-3d`（已存在）。

发布前：

1. **敏感信息扫描。** 搜索 `C:\`、`D:\`、`Users`、`token`、`password`、`api_key`、内网 IP、邮箱、`Bearer`。任何命中都必须清除。
2. **许可证。** 保留 MIT，版权行为 `bietou123` 或用户指定名称。不写入其它第三方受限制代码（本项目零依赖，无此问题）。
3. **无外部资源。** 搜索 `http://`、`https://`、`cdn`、`unpkg`、`fonts.googleapis`，确认没有运行时加载。
4. **中文优先。** README、帮助面板、信息面板、提交说明均使用中文；代码标识符与 API 保持英文。
5. **数据来源。** README 中列出参考来源类型（NASA、ESA、IAU 等公开资料），不复制受版权保护的大段文字。
6. **估计值标注。** 所有"约""估计""区间"在 UI 与 README 中一致。

发布步骤：

```
git status
git add index.html README.md LICENSE docs/
git commit -m "P8: 完成六级尺度、真实银河几何与地月系"
git push origin main
```

发布后：

1. 在 GitHub 页面上确认渲染正常（不依赖 Pages，因为单文件可直接下载）。
2. 检查 Release 说明（若打标签）：中文，列出新增能力与已知限制。
3. README 顶部放一张截图（可选，若体积可控）。若截图超过 500KB，改为文字描述 + 外部链接（但外部链接不得是必需资源）。

### 10.7 README 结构

README 必须包含以下章节，顺序固定：

1. **一句话简介**：零依赖、单文件、真实银河系的三维可视化。

3. **快速开始**：下载 `index.html`，双击打开。无需安装、无需服务器。

5. **怎么操作**：鼠标、触屏、键盘三张表。
6. **科学说明**：数据来源、比例压缩说明、争议标注。
7. **画质与性能**：`?quality=` 参数、自动降级。
8. **深链接**：哈希表。
9. **目录结构**：`index.html`、`docs/`、`tools/`。
10. **开发说明**：单文件约束、如何修改数据表。
11. **许可证**。

第 4、5、6 章必须用中文。技术名词（WebGL、SBbc、AU、kpc）保留原文。

### 10.9 已知限制的写法

诚实地写出限制，比假装没有更有价值。建议在 README 末尾加"已知限制"：

1. 银河系粒子是统计性示意，不是逐星测绘；旋臂位置基于大尺度巡天模型，不能用于天文导航。
2. 太阳系行星的大小与轨道距离经过非线性压缩，不对应同一比例尺。
3. 银河层中邻近恒星的位置沿"太阳附近放大示意区"排列，距离被显著放大。
4. 行星与月球表面为程序化生成，不宣称是真实影像。
5. 本星系群只包含主要成员与若干示意矮星系，不是完整目录。
6. 未模拟引力演化、碰撞、超新星等动态事件。
7. 月食、日食未模拟（可作为未来扩展）。

这样写不会削弱项目，反而让用户知道该信任什么、不该信任什么。

### 10.10 十卷收束

本规格到此结束。它定义的不是一个"好看的银河动画"，而是一个有层级、有依据、有说明的三维宇宙浏览器：

- 每一层都有科学依据；
- 每一次下钻都有明确的目标；
- 每一个对象都能被点击并读到介绍；
- 每一处视觉压缩都被标注。

用户在项目开始时说的是"继续优化"，但真正的要求是"别糊弄我"：银河不能是一根长条，放大不能只有一个去处，别的星系不能只是无名光斑，太阳系往里还应该能走到月球。本规格的全部工作，就是把这些"不能"变成"能"，并且让每一个"能"都能被截图和代码证明。
