# 第零卷　总纲与阅读指南

> 这不是一份"照着敲就能出画面"的代码说明，而是一份把用户口语需求翻译成可验收工程规格的文档。十卷正文加附录合计超过十万字，逐条回答同一个问题：用户说"不对啊"的时候，到底哪里不对，怎么改才算对。

---

### 0.1 这份规格解决什么问题

项目起始于一句"继续优化"，但真正的要求在后续十几轮对话里逐步显形：

1. 银河系被画成了**一根长条**，看不出来它是旋涡星系；
2. 放大**只能进入太阳系**，点别的地方也进太阳系；
3. 用户发现"别的星系呢"，说明尺度**只做了两级**；
4. 用户要求"**按真实的银河系来建模**"，说明之前是示意性光斑而非有据可依的结构；
5. 用户要求"太阳系再放大可以显示**地月系**"，说明下钻链条断在行星。

这五条合起来，本质是同一个问题：**层级不清、依据不明、标注不全**。所以本规格的核心不是"加特效"，而是重建一套分层结构，并让每一层的存在都有科学依据，每一次跳转都有明确目标，每一处视觉压缩都有说明。

### 0.3 三条最重要的设计决策

**决策一：银河必须能侧看。**

用户问"银河系不是长条吗"，不是要一根长条，而是指出原本的模型只有俯视一种形态。正确做法是提供三视角：俯视看旋臂结构，侧视看光带与核球鼓起，内部看横贯天空的银河带与大裂缝。第三卷定义切换机制，第二卷定义几何，第六卷定义光照与混合。

**决策二：下钻必须有依据。**

原代码在相机半径小于 `diveR` 时无条件调用 `diveToSolar()`，这是"放大只能到太阳系"的唯一根因。正确做法是：先判断屏幕中心对准了什么对象，再看该对象的屏幕尺寸是否足够大（太阳 70px、恒星 50px、星系 80px），同时满足才下钻。没有对准，就停在最小半径并给出提示。

**决策三：真实性与可读性必须同时成立。**

真实比例下太阳系无法观看，银河系无法区分结构。因此必须做压缩，但每一处压缩都要在比例尺、图例或面板中标注。宁可承认"这里放大了 3 倍"，也不要让用户误以为看到的是真实比例。

### 0.4 建议的阅读顺序

- **实现者**：第一卷 → 第三卷 → 第八卷 → 第九卷，然后按需查阅第二、六、七卷。先建立尺度与状态机的骨架，再填细节。
- **评审者**：第十卷 → 第一卷 → 第二卷。先看验收标准，再核对科学事实，最后看图。
- **只想改一个地方的人**：附录 A.3（单位换算）+ 第八卷 8.2（CFG）。绝大多数视觉参数都在 CFG 与数据表里，不需要动渲染代码。

### 0.5 验收的最短路径

如果时间有限，只做这三件事就能回答用户的全部质疑：

1. 按 `2` 切换侧视，画面变成一条中间鼓起的光带 —— 回答"银河系不是长条吗"。
2. 把视角移开太阳后滚轮放大到最小，停在原地并提示"点击太阳或其他恒星以进入" —— 回答"为什么放大只能到太阳系"。
3. 向外拉远进入本星系群，看到 M31 比银河系更大、LMC/SMC 紧邻银河系，点开有中文介绍 —— 回答"别的星系呢"。

这三件事对应第九卷的 P2、P3、P4，是投入产出比最高的三个阶段。
