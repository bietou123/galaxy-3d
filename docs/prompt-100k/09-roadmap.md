# 第九卷　实施路线图、风险与回滚

> 这份规格如果一次性全部实现，风险极高：粒子生成、着色器、状态机、七种新场景同时改动，任何一处出错都难以定位。本卷把工作切成 8 个阶段，每阶段都能独立验收、独立提交、独立回滚。任何阶段失败，项目仍停留在上一个可运行状态。

### 9.2 P0：基线冻结

目的：在改动前留下"已知可运行"的参照。

- 用 `git tag v0.9-baseline` 标记当前提交。
- 用无头浏览器截三张图：默认银河、太阳系、行星聚焦。
- 记录当前粒子数、平均帧时间、文件大小。
- 把这组数据写进 `docs/BASELINE.md`。

为什么要做：后续任何一阶段的视觉效果退化，都可以用这组截图对比，而不是凭记忆判断"好像变暗了"。

### 9.3 P1：银河几何重建

顺序：

1. **随机与噪声工具先落地。** `mulberry32`、`gaussian`、`fbm3` 必须先实现并测试，因为它们被所有构建函数依赖。测试方法：固定种子生成 10 万个数，统计均值与方差，检查是否接近理论值。
2. **构建中央棒与核球。** 先用 2 万粒子看看形状对不对，再提升到 7 万。验收：从俯视角度看，是一条中点最亮、两端渐隐的短棒，方位角 25°。
3. **构建薄盘与厚盘。** 指数盘采样，中心到边缘平滑衰减。验收：俯视时盘面有柔和的外缘，侧视时有厚度。
4. **构建四条旋臂。** 对数螺旋 + 高斯扰动。验收：四条臂从棒端甩出，宽度随半径增加，亮度不均。
5. **加入猎户臂与太阳位置。** 验收：太阳标记位于猎户臂内缘，不在臂间空隙。
6. **加入银晕与球状星团。** 验收：侧视时盘外有一层淡淡的球状散射，不是纯黑。

风险：

- 旋臂太"完美"会像风车。缓解：加入 ±8° 的相位扰动、沿臂的亮度噪声、起始半径差异。
- 核球与棒脱节。缓解：棒与核球共用方位角，核球第二层沿棒方向收窄。
- 粒子过多导致构建时间超过 3 秒。缓解：构建分片异步，先出低密度版本。

回滚：P1 的所有改动集中在构建函数与 CFG，`git revert` 单个提交即可回到旧粒子系统。

### 9.4 P2：暗尘、HII 与三视角

顺序：

1. **暗尘层。** 先实现混合模式与一层稀疏粒子，确认"能压暗背景"而不是"画黑点"。再加密到 2.5 万粒子，加入沿旋臂内侧的分布与噪声调制。
2. **HII 区。** 沿旋臂放置 300–600 个团块，每个 20–80 粒子。验收：粉紫色斑点成串出现在旋臂亮结，不是随机撒点。
3. **三视角切换。** 新增 `viewMode`，实现相机到俯视、侧视、内部光带的补间。
4. **内部光带视角的曝光调整。** 进入盘内时整体亮度下调，近处粒子不能过曝。

验收的关键一张图：侧视图必须是"一条横贯的细长光带，中间鼓起"。这张图就是用户问"银河系不是长条吗"的直接答案。

风险：

- 暗尘用错混合模式，画面变成一片黑烟。缓解：先用 200 个粒子做最小实验，确认公式 `dst = dst * (1 - a)` 的效果，再扩展。
- 内部视角过曝。缓解：按相机距离对粒子亮度做额外衰减，并在内部模式下限制核球辉光。

回滚：暗尘与 HII 是独立 VBO，可通过 CFG 开关整体关闭，不影响其它层。

### 9.5 P3：状态机与下钻判定

这是最关键、也最容易出错的一阶段。

顺序：

1. **定义 LAYER / PHASE / LAYER_CAM。** 先不改渲染，只搭状态机骨架，用 `console.log` 验证转移。
2. **实现 `transitionTo`。** 先不接实际的场景渲染，只做相机补间与状态切换，用"文字标题变化"验证。
3. **删除无条件 `diveToSolar()`。** 全项目搜索 `diveR` 与 `diveToSolar`，把调用点改成 `tryDive()`。
4. **实现 `tryDive()`。** 检查屏幕中心是否对准可进入对象，对准才下钻。
5. **接入拾取。** 点击对象进入对应层级。
6. **实现返回栈。**

验收清单（必须逐条手动测试）：

- 在银河层任意位置滚轮放大到最小半径，若未对准太阳，不进入太阳系。
- 点击太阳标记，进入太阳系。
- 点击南门二标记，进入南门二恒星系统（即使 P5 未完成，也要有占位场景）。
- 浏览器后退或按 `Esc`，回到银河层，相机位置正确。
- 快速连续点击两个不同对象，不出现黑屏或卡死。

风险：

- 状态机与渲染耦合，过渡期间画面读取到不一致的 `layer`。缓解：过渡期间渲染旧层与新层同时存在，用 alpha 控制，直到完成回调再切换 `layer`。
- 补间回调堆积。缓解：只保留一个补间对象，不使用回调数组。

回滚：状态机可以整体用 CFG 的 `legacyStateMachine: true` 开关回到旧的四状态实现。保留这个开关直到 P8 发布前，发布时删除。

### 9.6 P4：本星系群层

顺序：

1. **建立 L-1 尺度与坐标系。** 银河系原点、M31 位于 2,540 wu。
2. **代理星系渲染。** 先做三个大星系的椭圆盘粒子，再做矮星系。
3. **标签。** 中文名 + 编号 + 距离，两行。
4. **信息面板。** 复用行星面板的骨架，替换字段。
5. **进入与返回。** 从银河层向外拉远进入，点击银河系返回。

验收：

- 能看到银河系、M31、M33 三个明显不同的星系。
- M31 比银河系更大，且倾斜角度不同。
- LMC/SMC 紧邻银河系，不在盘内。
- 每个有名字的星系点开后有一段可读的中文介绍。
- 拉远/拉近过渡不白屏。

风险：

- 代理星系的粒子太少，像一团噪点。缓解：保证核心 billboard 足够柔亮，粒子只负责外围形态。
- 尺度太大导致深度缓冲精度不足。缓解：`near` 动态调整，或按层重置投影矩阵。

回滚：L-1 层是新增代码，不修改既有层。若出问题，可通过隐藏"本星系群"按钮与禁用向外拉远来退回。

### 9.7 P5：恒星系统层

顺序：

1. **恒星数据表。** 先录入 6 颗：太阳、南门二、巴纳德星、天狼星、天苑四、织女星。
2. **恒星球体渲染。** 颜色按光谱型，加光晕。
3. **行星轨道（B/C 级）。** 只有确认行星的系统画实线轨道，候选行星画虚线。
4. **恒星标记在银河层中的位置。** 按"邻近恒星放大示意"排列，并标注距离已放大。
5. **进入与返回。**

验收：

- 南门二显示 A、B、C 三星，A/B 互绕，比邻星在远处。
- 天狼星显示 A 与 B，B 明显更小。
- 巴纳德星不显示实线行星轨道，显示"候选，尚未确认"。
- 织女星只有恒星本体与资料，没有编造的行星。

风险：

- 多星系统的比例失真。缓解：在三合星层使用独立的局部尺度，并在面板写出真实距离。
- 用户误以为标记位置就是真实位置。缓解：图例明确写"邻近恒星距离已放大显示"。

回滚：恒星层独立，标记可从银河层标签系统移除。

### 9.8 P6：地月系层

顺序：

1. **尺度与相机。** 地球半径 1.0，月球 0.273，距离 60.3。
2. **地球渲染。** 程序化大陆、海洋、极冠、大气辉光。
3. **月球渲染。** 灰色月海、陨石坑、无大气。
4. **公转与潮汐锁定。** 月球绕地运动，同时自转同步，始终保持同一面朝向地球。
5. **月相。** 太阳方向固定，月相由公转自然产生。
6. **信息面板与时间控制。**

验收：

- 地球直径约是月球的 3.7 倍（视觉上正确）。
- 地月距离足够远，不是"月球贴着地球"。
- 月球始终同一面朝向地球，背面不可见。
- 从新月到满月，月球的亮面从无到有，而不是贴图切换。
- 地球昼夜分界线随自转移动。

风险：

- 潮汐锁定写错，月球乱转。缓解：每帧用 `lookAt(moonPos, earthPos)` 构造月球模型矩阵的旋转部分，自转角 = 公转角。
- 月相与光照方向不一致。缓解：光照方向与"太阳在世界坐标系中的固定方向"统一，不随相机变化。
- 真实比例下月球太小，用户看不清。缓解：提供"放大月球 3 倍"开关，并明确标注。

回滚：地月系独立场景，入口按钮可关闭。

- 无 `console.error`。
- 所有中文文案无乱码。

- 移动端可用（至少模拟器验证）。

### 9.12 性能预算

各阶段必须守住的时间预算（1080p，集成显卡）：

- 首帧：≤ 1,500ms（含着色器编译与低密度粒子生成）。
- 完整纹理生成完成：≤ 6,000ms，分片不阻塞。
- 稳定帧时间：
  - 银河层 high：≤ 33ms（30 FPS）
  - 银河层 low：≤ 41ms（24 FPS）
  - 本星系群层：≤ 25ms（40 FPS）
  - 太阳系层：≤ 25ms
  - 地月系层：≤ 25ms
- 单帧 CPU 时间（不含 GPU）：≤ 8ms。超出说明 JS 在做不该做的事，例如每帧重建缓冲区或每帧查询 uniform 位置。
- 标签更新：≤ 1ms。
- 拾取：≤ 0.5ms（仅在事件触发时）。

### 9.13 提交粒度与信息

每个阶段至少一次提交，提交信息格式：

```
P1: 重建银河几何（中央棒 + 四条旋臂 + 薄厚盘）
P2: 加入暗尘带与内部光带视角
P3: 状态机重构，移除无条件下钻
```

提交前必须：

- 本地双击打开验证一次。
- 无头截图看一眼。
- `git status` 无临时文件、无截图残留。
- 不提交生成的大图与测试脚本。

### 9.14 里程碑判定

项目可以宣布"完成"的条件：

1. 第六至八卷的验收标准全部通过。
2. 用户提出的 22 条需求（R01–R22）逐条对照，无遗漏。
3. 发布版本在干净环境（清空缓存、新浏览器配置）中双击可运行。
4. README 能让新用户 3 分钟内理解"这是什么、怎么看、能看什么"。
